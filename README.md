# 네이버 상품 리뷰 블로그 생성기

상품 페이지 URL 하나로 상위 노출을 노리는 리뷰 글을 만든다. 단순 GPT 글 생성기가 아니라
상품 분석 → SEO 전략 → 11단 구조 집필 → AI 냄새 제거 → 품질 채점 → 이미지 배치까지
거치는 파이프라인이다.

## 파이프라인

```
상품 URL
   │
   ├─ scrape/product.py        본문·가격·스펙표 수집 (requests → Playwright 폴백)
   │                           전역 메뉴·UI 라벨은 걷어내고 상품 내용만 남긴다
   ├─ media/product_images.py  썸네일 + 상세설명 이미지 수집 (지연 로딩 대응)
   │
   ├─ ai/analyst.py            특징·타깃·시나리오·구매고민·장단점·FAQ·추천대상 추출
   ├─ ai/focus.py              상세 이미지를 눈으로 읽고 집중 포인트 3안 제시 → 사용자 선택
   ├─ ai/roundup.py            여러 상품의 공통점·조합 이유 → 묶어 쓰는 원고
   ├─ ai/seo.py                키워드 전략, 검색의도/타입/경쟁도, H1·H2·H3 설계
   ├─ ai/writer.py             11단 구조로 집필 (산문은 AI, 서식은 파이썬)
   ├─ ai/humanizer.py          문체 계측 → 기계적인 지점만 재작성
   ├─ ai/critic.py             100점 채점
   └─ ai/reviser.py            80점 미만이면 지적된 부분만 수정 후 재채점
   │
   ├─ media/evaluator.py       다운로드·품질평가·긴 이미지 분할·중복 제거(dHash)
   ├─ media/planner.py         슬롯별 이미지 배정
   │
   ├─ render/html.py           미리보기 및 타 플랫폼용 HTML
   └─ render/naver_blocks.py   네이버 에디터 조작 목록
   │
   └─ publish/naver_blog.py    Playwright 로 임시저장 또는 발행
```

## 집중 포인트 선택

장점을 골고루 나열한 글은 아무것도 각인되지 않는다. 그래서 집필 전에 한 번 멈춘다.

상품 상세페이지는 설명 대부분이 이미지 안에 글자로 박혀 있어서, HTML 텍스트만 긁으면
정작 중요한 소구점을 놓친다. 그래서 상세 이미지를 내려받아 AI 에게 **직접 보여주고**
(비전 입력) 3안을 받는다.

제안은 마케팅 각도가 아니라 **상품이 실제로 가진 기능·사양·구성**이어야 한다.
"가성비를 어필한다" 같은 건 글쓰기 방법이지 상품의 포인트가 아니다. 그래서 근거를
상세페이지에서 그대로 인용하게 하고, 인용할 게 없으면 그 안을 내지 못하게 막았다.

```
1. 에이밍 기능
   상세페이지 근거 UPL2000의 가장 큰 장점은 역시 에이밍 모드입니다.
   도움 되는 사람  방향 감각이 부족한 골프 초보자
   놓치는 것       고급 골퍼에게는 크게 필요하지 않을 수 있음
2. 외부 LCD 화면 ...
3. 슬로프 보정 ...

어느 점에 집중할까요? (1/2/3 · r=다시 제안받기 · s=포인트 없이 진행)
```

마음에 드는 안이 없으면 `r` 로 다시 받는다. 이때 "휴대성이나 무게 쪽으로" 같은 방향을
알려주면 그 쪽으로 다시 뽑고, 이미 거절한 안은 다시 내지 않는다.

고른 포인트는 SEO 키워드 전략과 집필 프롬프트에 함께 실려, 글 전체가 그 점으로 수렴한다.
`--auto-focus` 를 주면 묻지 않고 1안으로 진행한다.

## 여러 상품을 한 글로

`--url` 을 두 번 이상 주면 한 상품 리뷰가 아니라 **조합 소개글**을 쓴다. 어떤 상품을
묶을지는 직접 고른다. 이쪽은 공통점과 같이 쓰는 이유만 찾고, 상품마다 소개와 구매
링크를 넣는다. 다섯 개부터는 쇼핑 목록이 되므로 4개까지만 받는다.

글 구조는 한 상품 리뷰와 다르다.

도입 · 공통점 · 같이 쓰는 장면 · 상품별 소개(이미지+구매링크) · 비교표 · 추천 대상 ·
FAQ · 총평 · 상품별 썸네일+구매링크

집중 포인트도 한 상품의 기능이 아니라 **조합이 공유하는 축**을 고른다.

## 글 구조

제목 · 도입부 · 문제제기 · 상품소개 · 주요특징 · 실사용 시나리오 · 장점 · 아쉬운 점 ·
FAQ · 총평 · CTA

구조와 서식은 파이썬이 고정하고 AI 는 산문만 쓴다. 서식까지 AI 에게 맡기면 실행할
때마다 결과가 달라져 품질이 들쭉날쭉해진다.

구매 링크는 세 곳에 들어간다. 주요 특징 뒤와 장점 뒤에 짧은 안내 문구로 한 번씩,
마지막에는 상품 썸네일과 묶어서 한 번. 네이버 에디터는 이미지에 링크를 거는 자동화가
불안정해서, 썸네일 바로 아래에 URL 을 한 줄로 넣는다. 에디터가 이를 자동으로 링크로
바꿔준다.

## AI 냄새 제거

"사람처럼 써줘"라는 요청만으로는 잘 고쳐지지 않는다. 그래서 파이썬이 먼저 문체를
수치로 재고, 걸린 항목만 집어서 다시 쓰게 한다.

| 계측 항목 | 판정 기준 |
| --- | --- |
| 문장 길이 변동계수 | 0.45 미만이면 기계적 |
| 종결 어미 다양성 | 0.35 미만이면 단조로움 |
| 반복 표현 | 같은 3어절이 3회 이상 |
| AI 상투어 | "결론적으로", "뿐만 아니라" 등 22개 목록 |
| 지나치게 긴 문장 | 90자 초과 |

재작성 결과가 오히려 나빠지면 이전 원고를 지킨다.

## 이미지 우선순위

1. 상품 상세페이지 이미지
2. 상품 대표 이미지(썸네일)
3. Pexels / Unsplash 스톡
4. AI 생성

슬롯마다 어울리는 출처가 달라서, 전체 우선순위를 지키되 슬롯별로 선호 순서를 따로 둔다.
실사용 시나리오 자리에 스펙 이미지를 넣으면 어색하고, 주요 특징 자리에 스톡 사진을
넣으면 정보가 없기 때문이다.

| 슬롯 | 위치 | 선호 출처 |
| --- | --- | --- |
| hero | 도입부 | 썸네일 → 상세 → 스톡 |
| product | 상품소개 | 상세 → 썸네일 → 스톡 |
| feature | 주요특징 | 상세 → 썸네일 → 스톡 |
| lifestyle | 실사용 | 스톡 → AI → 상세 |
| infographic | FAQ | 상세 → 스톡 → AI |
| cta | 총평 | 썸네일 → 스톡 → AI |

상세페이지 이미지는 860×5000 처럼 세로로 긴 경우가 많아 읽기 좋은 비율로 잘라 쓴다.
같은 사진을 크기만 바꿔 여러 번 올린 경우가 흔해서 지각 해시(dHash)로 중복을 걸러낸다.

## 사용

`--url` 은 **본문에 넣을 구매 링크**다. 브랜드 커넥트 제휴 링크를 그대로 넣으면 된다.
내용과 이미지를 긁어올 **실제 판매 페이지**는 따로 물어본다. 제휴 링크는 중간 페이지를
거치느라 상품 내용이 덜 잡히는 경우가 있어서 둘을 나눠 받는다. 모르면 엔터를 치면
구매 링크를 따라가서 긁는다. `--page-url` 로 미리 넘기면 묻지 않는다.

```
구매 링크  https://naver.me/Gy3xcwOD
이 링크는 블로그 본문의 구매 링크로 그대로 들어갑니다. (제휴 추적 유지)

내용과 이미지를 긁어올 실제 상품 판매 페이지 주소를 알려주세요.
> https://brand.naver.com/finevu/products/13030260544
```

```powershell
# 원고와 이미지만 생성. HTML 미리보기까지 열기
python main.py post --url "https://구매링크" --dry-run --open

# 판매 페이지를 미리 넘겨 묻지 않게 하기
python main.py post --url "https://구매링크" --page-url "https://판매페이지"

# 여러 상품을 묶어 한 글로 (2~4개). 조합은 직접 고른다
python main.py post --url "https://구매링크1" --url "https://구매링크2" --dry-run

# 실제 포스팅
python main.py post --url "https://구매링크"

# 이미 만든 결과물만 네이버에 다시 올리기 (원고 생성 생략)
python main.py upload
python main.py upload --from output/20260912_151642_파인캐디_UPL2000

# 수정 제안 마크다운으로 article 을 다시 쓴 뒤 올리기
python main.py upload --md suggestions.md
python main.py upload --from output/폴더 --md C:\path\to\notes.md

# 크롤링이 막히는 사이트는 설명을 직접 넘긴다
python main.py post --url "https://..." --desc "상품 설명"

# 이미지 수집을 건너뛰어 빠르게 원고만 확인
python main.py post --url "https://..." --dry-run --no-images

# 집중 포인트를 묻지 않고 1안으로 진행
python main.py post --url "https://..." --auto-focus
```

결과는 `output/날짜_제목/` 에 저장된다.

| 파일 | 내용 |
| --- | --- |
| `article.html` | 서식이 적용된 미리보기. 티스토리·워드프레스에도 쓸 수 있다 |
| `suggestions.md` | 수정 제안만 적는 파일. 이 내용으로 article 을 다시 쓴다 |
| `article.json` | 다시 쓸 때 쓰는 원고 원본 |
| `naver.txt` | 네이버에 실제로 입력될 내용 |
| `report.json` | 상품 분석, SEO 전략, 시도별 점수 |
| `images/` | 슬롯에 배정된 이미지 |

## 상품을 못 읽으면 멈춘다

가장 위험한 실패는 오류가 아니라 **그럴듯한 거짓말**이다. 상품 페이지가 죽어 있으면
크롤러는 메뉴와 푸터만 가져오는데, 그대로 두면 AI 가 "네이버 멤버십 적립", "통신판매
중개자" 같은 것을 상품의 특징이라 믿고 있지도 않은 상품의 리뷰를 완성해 버린다.

그래서 집필 전에 두 번 막는다.

1. `상품이 존재하지 않습니다`, `삭제되었거나`, `Access Denied`, 네이버 로그인 페이지로의
   리다이렉트를 감지하면 중단한다. 안내문은 페이지 앞부분만 본다. 후기 본문까지 뒤지면
   평범한 문장에 걸려 멀쩡한 상품을 막게 된다.
2. 가격 · 스펙표 · 상세 이미지 · 본문 길이 중 최소 두 개는 잡혀야 진행한다.
   못 찾은 항목을 알려주고 멈춘다.

판매 페이지가 막히면 구매 링크로 자동으로 한 번 더 시도하고, 그래도 안 되면 45초씩
쉬었다가 최대 3회까지 다시 해본다. `smartstore.naver.com` 직접 주소는 자동 접근을
로그인 페이지로 돌려보내는 일이 잦은데, 같은 상품도 제휴 링크로 들어가면 통과하는
경우가 많아서다.

## 네이버 상품 정보를 읽는 방법

스마트스토어는 자동 접근을 막으면 화면 본문을 비우거나 로그인으로 보낸다. 억지로
페이지를 뚫지 않고, 아래 순서로 공개된 정보만 읽는다.

1. 블로그 발행에 쓰는 네이버 로그인 세션(`storage/naver_session.json`)이 있으면
   상품 페이지에도 그대로 쓴다. 한 번이라도 `python main.py post` 로 로그인한 적이
   있으면 세션이 남아 있다.
2. 화면을 스크롤하기 전에 `window.__PRELOADED_STATE__.simpleProductForDetailPage` 에서
   상품명·가격·대표 이미지를 읽는다. 본문이 비어도 이 JSON 은 첫 응답에 들어 있다.
3. 그다음에야 상세 이미지를 위해 스크롤한다. 페이지가 오류 화면으로 바뀌면 즉시 멈춘다.

## 네이버가 막을 때

짧은 시간에 여러 번 긁으면 네이버가 차단한다. 이때 HTTP 429 로 솔직하게 알려주기도
하지만, **멀쩡한 상품을 "상품이 존재하지 않습니다" 로 보여주기도 한다.** 삭제된 상품과
구분이 안 되니, 그 메시지를 봤다고 바로 상품이 없어졌다고 단정하면 안 된다.

특히 조심할 것이 하나 있다. 스마트스토어는 스크롤할 때 나머지를 지연 로딩하는데,
차단 상태에서는 그 요청이 실패하면서 **페이지 전체가 오류 화면으로 갈아치워진다.**
즉 멀쩡히 뜬 상품 페이지를 이쪽에서 스크롤하다가 스스로 망가뜨리게 된다.

```
goto+3s  : TEEBOX 플라스틱 30개입 ... 골프티 화이트 : 티박스 골프
스크롤 1  : TEEBOX 플라스틱 30개입 ... 골프티 화이트 : 티박스 골프
스크롤 2  : 상품이 존재하지 않습니다.      <- 여기서 뒤집힌다
```

그래서 스크롤 전 상태를 들고 있다가 페이지가 오류로 바뀌면 그 스냅샷을 쓰고, 이미지
수집 쪽도 오류 화면을 감지하면 즉시 스크롤을 멈춘다. 그때까지 모은 이미지는 지킨다.

**주 1회 포스팅이면 겪을 일이 거의 없다.** 연달아 테스트할 때만 문제가 된다.

단축 링크가 실제로 도착한 주소도 함께 보여준다. 제휴 링크는 어디로 가는지 눈에 보이지
않아서, 만료된 링크를 붙여놓고도 모르는 경우가 많다. 여기서 만료를 확인했다면 판매
페이지를 찾아 `--page-url` 로 넘기면 된다. 본문 구매 링크는 원래 제휴 링크가 유지된다.

`--desc` 로 상품 설명을 직접 넣으면 이 검사를 건너뛴다.

## 업로드 전에 HTML 을 보고 제안으로 article 을 다시 쓴다

네이버 임시저장 직전에 `article.html` 미리보기가 열린다. 마크다운은 완성 원고가
아니라 **수정 제안**이다. Copilot 과 확인한 고칠 점을 `suggestions.md` 에 적으면
프로그램이 그 제안으로 article 을 다시 작성한다. 사진과 구매 링크 주소는 그대로 둔다.

`python main.py upload` 와 `python main.py post` 모두 이 단계를 거친다.
제안 파일이 이미 있으면 `--md` 로 넘긴다.

## 알아둘 제약

**네이버는 HTML 을 받지 않는다.** 스마트에디터가 실제로 지원하는 건 텍스트, 이미지,
인용구, 구분선 정도다. 표와 FAQ 아코디언은 자동화가 불가능해서 유니코드 기호로 시각적
구조를 만들어 넣는다. `article.html` 은 미리보기와 다른 플랫폼용이다.

**AI 이미지 생성은 기본 꺼져 있다.** Bayer myGenAssist API 에는 이미지 생성
엔드포인트가 없다. `.env` 의 `IMAGE_GEN_*` 에 외부 서비스(OpenAI 등) 정보를 넣으면
켜진다. 카테고리별 프롬프트 템플릿은 `media/prompts.py` 에 이미 설계되어 있다.

**처음에는 `POST_MODE=draft` 로 쓴다.** 임시저장만 하고 실제 발행은 네이버에서 직접
확인한 뒤 누르는 방식이다.

**대가성 문구는 지우지 않는다.** 쇼핑 커넥트처럼 판매 수수료를 받는 글에 이 문구가
없으면 표시광고법 위반이다. 본문 맨 위에 자동으로 들어간다. 기본 문구는 방문·구매가
잘 나는 쇼핑 커넥트 글의 표기를 따른다.

**주 1회 정도가 적당하다.** 매일 자동 포스팅하면 어뷰징 필터에 걸려 저품질 블로그로
분류될 수 있다.

## 사내망에서 생길 수 있는 문제

**SSL 오류로 외부 API 가 실패할 때.** 사내 SSL 검사 장비가 통신을 자체 서명
인증서로 가로채기 때문이다. `truststore` 가 파이썬이 윈도우 인증서 저장소를 쓰도록
바꿔서 해결한다. `requirements.txt` 에 포함되어 있다. 검증을 끄지 마세요.

**AI 응답이 비어서 올 때.** myGenAssist 는 `gpt-4o` 를 요청해도 `gpt-5-mini` 같은
추론 모델로 라우팅할 수 있는데, 이런 모델은 토큰을 추론에 먼저 쓴다. 한도가 모자라면
본문이 빈 채로 돌아온다. 프로그램이 추론에 몇 토큰을 썼는지 알려주므로 `max_tokens`
를 올리면 된다.

## 네이버 로그인이 안 될 때

쿠키만 보고 로그인 성공으로 처리하면, 만료된 세션인데도 "에디터에 내용 입력 중"으로
넘어간다. 지금은 글쓰기 화면이 실제로 열려야 로그인한 것으로 본다. 캡차가 뜨면
`.env` 의 `BROWSER_HEADED=true` 로 창을 띄운 뒤 직접 로그인한다. 네이버 홈이 보인
다음에 터미널에서 Enter 를 누르면 된다. 실패해도 창은 바로 닫지 않고, 로그인이
됐다면 세션을 저장해 다음 `upload` 에서는 다시 묻지 않는다.

업로드가 실패해도 원고는 `output/` 에 남아 있다. 처음부터 다시 만들지 말고
`python main.py upload` 로 올리기만 반복한다.

## 에디터 선택자가 바뀌었을 때

네이버는 CSS 클래스명을 수시로 바꾼다. "제목 입력란을 찾지 못했습니다" 같은 오류가
나면 `--debug` 로 실행해 `storage/screenshots/` 를 확인하고,
`publish/naver_blog.py` 위쪽의 선택자 목록에 새 값을 추가한다.
