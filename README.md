# 네이버 상품 리뷰 블로그 생성기

상품 페이지 URL 하나로 상위 노출을 노리는 리뷰 글을 만든다. 단순 GPT 글 생성기가 아니라
상품 정보 검증 → 고객·검색 의도 분석 → 핵심 메시지 → 개요 → 섹션별 집필 → 문체 통일 → 검수 →
부분 수정 → 이미지 배치까지 거치는 파이프라인이다.

## 파이프라인

```
상품 URL
   │
   ├─ scrape/product.py        본문·가격·스펙표 수집 (requests → Playwright 폴백)
   │                           전역 메뉴·UI 라벨은 걷어내고 상품 내용만 남긴다
   ├─ media/product_images.py  썸네일 + 상세설명 이미지 수집 (지연 로딩 대응)
   │
   ├─ ai/analyst.py            특징·타깃·시나리오·구매고민·장단점·추천대상 추출
   ├─ ai/focus.py              상세 이미지를 눈으로 읽고 집중 포인트 3안 제시 → 사용자 선택
   ├─ ai/roundup.py            여러 상품의 공통점·조합 이유 → 묶어 쓰는 원고
   ├─ ai/seo.py                키워드 전략, 검색의도/타입/경쟁도, H1·H2·H3 설계
   ├─ ai/staged/               단계별 집필 (기본). 사실 정리 → 핵심 메시지 → 개요 → 섹션 집필
   │                           → 문체 통일 → 검수 → 부분 수정 → 제목 → 조립
   ├─ ai/writer.py             예전 방식(legacy). 11단 구조를 앞·뒷부분 두 번에 집필
   ├─ ai/humanizer.py          문체 계측 → 기계적인 지점만 재작성 (legacy)
   ├─ ai/critic.py             100점 채점
   └─ ai/reviser.py            80점 미만이면 지적된 부분만 수정 후 재채점 (legacy)
   │
   ├─ media/evaluator.py       다운로드·품질평가·긴 이미지 분할·중복 제거(dHash)
   ├─ ai/image_screen.py       배송·교환·반품 안내 이미지 제거, 제품 설명 이미지만 남김
   ├─ media/planner.py         슬롯별 이미지 배정 (첫 이미지는 대표 썸네일)
   ├─ media/infographic.py     글 전체를 한 장으로 요약한 그림 생성
   │
   ├─ core/shopping_connect.py 구매 링크 -> 쇼핑 커넥트 상품 카드 정보
   ├─ render/html.py           미리보기 및 티스토리 본문 HTML
   └─ render/naver_blocks.py   네이버 에디터 조작 목록
   │
   ├─ publish/naver_blog.py    Playwright 로 임시저장 또는 발행
   └─ publish/tistory.py       네이버와 같은 원고(글·사진·구매 버튼)를 티스토리에 발행
```

## 뉴스 요약과 연관 상품 추천

분야별 최신 뉴스 10건을 게시 시각순으로 가져오고, 기사 제목·요약에서 규칙 기반 키워드와
이슈를 추출해 네이버 쇼핑 검색 결과 중 관련 상품 TOP 3을 보여 준다. 기사 원문에 근거하는
발췌형 요약이며 AI가 새 사실을 생성하지 않는다.

키는 두 종류다. NAVER API HUB 에는 쇼핑 상품 검색이 없어서 쇼핑은 NAVER Developers 키를 따로 쓴다.

| 용도 | 발급처 | `.env` 키 | 호출 주소 |
| --- | --- | --- | --- |
| 뉴스 (필수) | [NAVER API HUB](https://console.ncloud.com/naver-api-hub/subscription) | `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | `naverapihub.apigw.ntruss.com/search/v1/news` |
| 쇼핑 (선택) | [NAVER Developers](https://developers.naver.com/apps) 검색 API | `NAVER_SHOP_CLIENT_ID`, `NAVER_SHOP_CLIENT_SECRET` | `openapi.naver.com/v1/search/shop.json` |

쇼핑 키가 없거나 쇼핑 호출이 실패해도 뉴스 요약은 그대로 나오고, 이유만 안내한다.

```shell
python main.py news --category "IT"
```

파이썬에서 `news_blog.fetch_news_digest("패션")`을 호출하면 뉴스, 키워드, 이슈, 상품 추천을
`NewsDigest`로 받는다. 상품별 구매 주소는 `purchase_url`에, 추천을 못 가져온 이유는
`recommendation_note`에 담긴다. 이 기능은 기존 `core/shopping_connect.py`의 제휴 카드
생성과는 별개다.

## 집중 포인트 선택

장점을 골고루 나열한 글은 아무것도 각인되지 않는다. 그래서 집필 전에 한 번 멈춘다.

상품 상세페이지는 설명 대부분이 이미지 안에 글자로 박혀 있어서, HTML 텍스트만 긁으면
정작 중요한 소구점을 놓친다. 그래서 상세 이미지를 내려받아 AI 에게 **직접 보여주고**
(비전 입력) 3안을 받는다.

제안은 마케팅 각도가 아니라 **상품이 실제로 가진 기능·사양·구성**이어야 한다.
"가성비를 어필한다" 같은 건 글쓰기 방법이지 상품의 포인트가 아니다. 그래서 근거를
상세페이지에서 그대로 인용하게 하고, 인용할 게 없으면 그 안을 내지 못하게 막았다.

```
1. 에이밍 기능
   상세페이지 근거 UPL2000의 가장 큰 장점은 역시 에이밍 모드입니다.
   도움 되는 사람  방향 감각이 부족한 골프 초보자
   놓치는 것       고급 골퍼에게는 크게 필요하지 않을 수 있음
2. 외부 LCD 화면 ...
3. 슬로프 보정 ...

어느 점에 집중할까요? (1/2/3 · r=다시 제안받기 · s=포인트 없이 진행)
```

마음에 드는 안이 없으면 `r` 로 다시 받는다. 이때 "휴대성이나 무게 쪽으로" 같은 방향을
알려주면 그 쪽으로 다시 뽑고, 이미 거절한 안은 다시 내지 않는다.

고른 포인트는 SEO 키워드 전략과 집필 프롬프트에 함께 실려, 글 전체가 그 점으로 수렴한다.
5초 안에 입력을 시작하지 않으면 1안으로 자동 진행한다. 글자를 치기 시작하면 엔터까지 기다린다.
`--auto-focus` 를 주면 묻지 않고 바로 1안으로 진행한다.

## 여러 상품을 한 글로

`--url` 을 두 번 이상 주면 한 상품 리뷰가 아니라 **조합 소개글**을 쓴다. 어떤 상품을
묶을지는 직접 고른다. 이쪽은 공통점과 같이 쓰는 이유만 찾고, 상품마다 소개와 구매
링크를 넣는다. 다섯 개부터는 쇼핑 목록이 되므로 4개까지만 받는다.

글 구조는 한 상품 리뷰와 다르다.

도입 · 공통점 · 같이 쓰는 장면 · 상품별 소개(이미지+구매링크) · 비교표 · 추천 대상 ·
한눈에 보기 · 상품별 썸네일+구매링크

집중 포인트도 한 상품의 기능이 아니라 **조합이 공유하는 축**을 고른다.

## 여러 상품을 한 글씩 순서대로

`--each` 를 붙이면 묶지 않고 상품마다 따로 글을 만들어 1 → 2 → 3 → 4 순서로 올린다.
개수 제한은 없다. 한 상품이 실패해도 다음 상품은 계속하고, 끝에 성공·실패를 표로 보여준다.

```powershell
python main.py post --each --url "https://구매링크1" --url "https://구매링크2" --url "https://구매링크3"
```

상품 리뷰를 만들기 전에 네이버와 티스토리 로그인 상태부터 확인한다. 둘 다 로그인되어 있으면
바로 상품 리뷰로 넘어가고, 세션이 없으면 그 자리에서 로그인한다. 로그인에 실패하면 원고를
만들지 않고 멈춘다. `--tistory-only` / `--no-tistory` 로 빠지는 쪽은 확인하지 않으며,
`--dry-run` 이면 확인 자체를 건너뛴다.

`--page-url` 은 `--url` 과 같은 개수로 주면 순서대로 짝지어 쓴다. `--desc` 와 `--md` 는
모든 글에 같은 내용이 들어가므로 쓰지 않는다. 짧은 시간에 많이 올리면 어뷰징으로 보일 수
있으니 한 번에 몇 개만 넣는다.

## 글 구조

제목 · 도입부 · 상품이 필요한 이유 · 핵심 특징과 고객 이점 · 구체적인 사용 상황 ·
사용 방법과 활용 팁 · 추천 대상 · 구매 전 확인 사항 · 한눈에 보기 · 구매 안내

아쉬운 점은 따로 두지 않고 구매 전 확인 사항에 합친다. SEO 메타 설명은 `article.html` 의
`<meta name="description">` 과 `report.json` 에, 해시태그는 글 태그로 들어간다.
(예전 방식 `legacy` 의 구조는 문제제기 · 상품소개 · 주요특징 · 실사용 · 장점 · 아쉬운 점 · 한눈에 보기 · CTA 다.)

총평은 본문 문단으로 쓰지 않고 한눈에 보기 인포그래픽 안에 500~1000자로 넣는다.
네이버 본문의 소제목(■ 24, ▸ 19)은 에디터 툴바로 글자를 키우고 굵게 바꾼다.

구조와 서식은 파이썬이 고정하고 AI 는 산문만 쓴다. 서식까지 AI 에게 맡기면 실행할
때마다 결과가 달라져 품질이 들쭉날쭉해진다.

## 단계별 글 작성

한두 번의 큰 요청으로 글 전체를 쓰면 핵심이 흩어지고, 어느 문장이 어디서 나왔는지 확인할 수도
없다. 그래서 글을 단계로 나눠 쓴다(`ai/staged/`). 단계마다 AI 는 JSON 으로 답하고, 결과는 결과
폴더의 `stages/` 에 저장된다.

| 단계 | 하는 일 | 저장본 |
| --- | --- | --- |
| 1 상품 정보 검증·정리 | 원문에서 글에 써도 되는 사실만 뽑는다. 사실마다 원문 인용을 받고, 인용이 원문에 없으면 뺀다. 스펙표·가격은 코드가 직접 넣는다 | `01_facts` |
| 2 핵심 고객·검색 의도 | 기존 상품 분석·집중 포인트·SEO 전략을 그대로 쓴다 | `02_brief` `02_focus` `02_seo` |
| 3 핵심 메시지 | 고객의 문제에서 출발한 한 문장과 그 근거 | `03_message` |
| 4 개요 | 섹션별 소제목·목표·근거 사실, 메타 설명, 해시태그. 검색어는 코드가 섹션마다 한 번씩 나눠 맡긴다 | `04_outline` |
| 5 섹션별 본문 | 섹션 몇 개씩 나눠 쓴다. 묶음마다 저장해 쓴 섹션은 다시 쓰지 않는다 | `05_sections` |
| 6 흐름·문체 통일 | 연결 문장과 어미만 고친다. 검색어가 빠지는 변경은 버린다 | `06_unified` |
| 7 검수 | 코드 검사 + AI 검수 (아래 표) | `07_review` |
| 8 부분 수정 | 걸린 문장만 고치고 코드 검사를 다시 돌린다. 최대 `STAGED_MAX_FIX_ROUNDS` 회 | `08_fixed` |
| 9 최종 조립 | 제목 3안을 받아 1순위를 쓰고(검사에 걸리면 다음 순위), 기존 글 구조로 조립 | `09_titles` |

코드 검사(`ai/staged/checks.py`)는 AI 에게 맡기면 매번 달라지는 항목을 잡는다.

| 항목 | 기준 |
| --- | --- |
| 과장·효능 표현 | 최고의, 완벽, 1위, 역대급, 치료 등. 상품 원문에 그 말이 있을 때만 허용 |
| 구매 압박 | 지금 바로, 놓치면, 품절 임박, 오늘만 등 |
| 체험 단정 | 직접 써 보니, 사용해봤, 내돈내산 등 |
| 근거 없는 수치 | `숫자+단위`의 숫자가 상품 원문에 없으면 걸린다 |
| 검색어 | 한 문장 반복, 메인 키워드 밀도 2.5% 초과, 도입부 누락, 보조 키워드 4회 이상 |
| 반복·가독성 | 같은 3어절 3회 이상, 250자 넘는 문단, 110자 넘는 문장 |

사용 장면은 사실이 아니라 **제품이 쓰일 법한 순간을 상상해서** 그린다. 단 "직접 써 보니"처럼
써 본 것처럼 꾸미지 않고, 제품 사양은 확인된 사실 안에서만 쓴다. 그래서 사용 장면 섹션에서는
"출근 전 10분" 같은 시간 표현은 허용하고 W·kg·% 같은 사양 수치만 검사한다.

### 실패한 지점부터 다시

저장본에는 그 단계에 들어간 입력의 해시가 붙는다. 이어서 실행하면 입력이 같은 단계는 건너뛰고,
앞 단계가 바뀐 단계부터 다시 돈다. 상품 수집·이미지 내려받기·집중 포인트 선택도 다시 하지 않는다.

```powershell
# 섹션 집필 중 실패했다면 그 폴더로 이어서 만든다 (업로드 옵션은 post 와 같다)
python main.py post --resume output/20261017_020955_상품명 --dry-run

# 특정 섹션만 다시 쓴다. 다른 섹션 문장은 그대로 두고, 통일·검수·수정도 그 섹션에만 한다
python main.py rewrite --from output/폴더 --section tips --section checks

# 제목만 다시. 이미 쓴 제목은 피해서 3안을 받고 1순위를 쓴다
python main.py rewrite --from output/폴더 --title
```

섹션 이름: `intro`(도입) `need`(필요한 이유) `features`(특징·이점) `scenes`(사용 상황)
`tips`(사용법·팁) `audience`(추천 대상) `checks`(구매 전 확인) `summary`(한눈에 보기) `cta`(구매 안내).
`rewrite` 는 올리지 않는다. 확인한 뒤 `python main.py upload --from 폴더` 로 올린다.

### 예전 방식과 비교

예전 프롬프트(`ai/prompts.py`, `ai/writer.py`)는 지우지 않았다. `.env` 의 `WRITER_MODE=legacy` 나
`--writer legacy` 로 예전 방식을 쓸 수 있고, 단계별로 만든 결과 폴더에서 비교할 수 있다.

```powershell
python main.py compare --from output/폴더
```

같은 분석·SEO 저장본으로 예전 방식 원고를 만들어 본문 길이, AI 품질 총점, SEO 점수, 문체 자연스러움,
코드 검수 지적 수, AI 호출 수를 나란히 보여준다. 예전 방식 원고는 `compare_legacy.html`, 수치는
`compare.json` 에 남고 `article.json` 은 건드리지 않는다. **실제 AI 를 호출하므로 비용이 든다.**

여러 상품을 묶는 조합 글(`--url` 여러 개)은 지금처럼 예전 방식으로 쓴다.

### 설정

| 항목 | 기본값 | 의미 |
| --- | --- | --- |
| `WRITER_MODE` | `staged` | `staged` 단계별 집필, `legacy` 예전 방식 |
| `STAGED_SECTION_BATCH` | `3` | 한 번에 쓸 섹션 수. 늘리면 호출 수가 줄고 섹션별 집중도는 떨어진다 |
| `STAGED_MAX_FIX_ROUNDS` | `2` | 검수 후 부분 수정 최대 횟수 |
| `STAGED_AI_REVIEW` | `true` | `false` 면 AI 검수 없이 코드 검사만 한다 |

한 글에 드는 AI 호출은 약 15회다(분석·집중 포인트·SEO 3, 단계별 집필 10~12, 품질 평가 1).
호출 수는 `report.json` 의 `ai_calls` 에 남는다.

## 한눈에 보기 — 인포그래픽

예전에는 이 자리가 FAQ 였다. Q 와 A 를 줄줄이 늘어놓으니 정작 **한눈에 들어오지
않아서**, 글 전체를 한 장으로 요약한 그림으로 바꿨다.

```
┌──────────────────────────────┐
│ [한눈에 보기] 상품명   (초록 배너)│
├───────────────┬──────────────┤
│ ★ 특징 1      │ ⚡ 특징 2      │
│ ◆ 특징 3      │ ♥ 특징 4      │
├───────────────┼──────────────┤
│ ✔ 이런 분께 추천│ ✖ 이런 분께 비추천│
├──────────────────────────────┤
│ 총평 (체감 말풍선 / 결론 말풍선) │
└──────────────────────────────┘
```

**HTML 이 아니라 이미지다.** 스마트에디터는 HTML 을 받지 않으므로, '한눈에 보이는 것'
을 네이버 본문에 넣으려면 결국 그림이어야 한다. 그래서 CSS 로 꾸미지 않고 Pillow 로
직접 그린다(`media/infographic.py`). 글자가 뭉개지지 않게 2배 크기로 그린다.

내용은 이미 만들어 둔 것을 다시 쓴다. 특징은 `brief.features`, 추천·비추천은
`brief.recommended_for`, 총평은 원고의 총평 박스(verdict)에서 가져온다. 총평은 웹툰
형식(직접 써본 솔직 체감 말풍선, 최종 결론 & 한줄 요약 말풍선과 귀여운 캐릭터 표정)
으로 시각화되며, 150~300자로 간결하게 축약해 들어간다. 그림이 들어가면 본문의 총평 박스는 지운다. AI 를 한 번 더 부르지 않는다. 묶음 글은 개별 상품 대신
**조합의 공통점**을 넣는다.

한 장에 담기는 양은 특징 4개, 추천·비추천 각 2개다. 항목은 2줄까지만 두고 넘치면
말줄임표로 자른다. 총평은 핵심 2문장씩으로 축약해 말풍선에 넣는다.

이 자리에는 사진을 넣지 않는다. "한눈에 보기" 밑에 상세페이지 사진이 들어가면 제목과
그림이 따로 놀기 때문이다. 그림을 못 그리면 그 자리는 통째로 빠진다.

글꼴은 윈도우 기본 맑은 고딕을 쓴다. 체크(✓)와 엑스(✕)는 맑은 고딕에 글리프가 없어
두부(□)로 나오므로 선으로 직접 그린다.

macOS에서는 시스템 한글 글꼴인 Apple SD Gothic Neo를 사용한다. 네이버 본문 입력은
macOS의 Command+V, Windows의 Control+V로 붙여넣으며, 제목과 본문 텍스트가 실제로
에디터에 들어갔는지 확인한 뒤 저장한다.

구매 링크는 세 곳에 들어간다. 핵심 특징 뒤와 추천 대상 뒤에 한 번씩, 마지막 구매 안내에 한 번.
(예전 방식은 주요 특징 뒤, 장점 뒤, 마지막 총평 뒤.)

세 곳 모두 **쇼핑 커넥트 상품 카드**로 들어간다. 썸네일·상품명·판매처가 한 덩어리로
보이는 그 카드다. 다만 만드는 방법이 출력물마다 다르다.

| 출력물 | 넣는 방법 |
| --- | --- |
| `article.html` | 네이버 본문과 같은 마크업(`se-shopping-connect`)을 직접 그린다 |
| 네이버 블로그 | 툴바의 **쇼핑커넥트** 버튼을 눌러 에디터가 직접 넣게 한다 |

### 네이버 쪽은 왜 다른가

스마트에디터는 HTML 을 받지 않는다. 게다가 카드에 필요한 `affiliateProductId` 는 구매
링크 어디에도 없다. 그 번호는 **내 쇼핑 커넥트 상품 목록**에서 나오기 때문이다. 즉
카드는 붙여넣는 것이 아니라 에디터 안에서 골라 넣어야 하는 물건이다.

그래서 업로드할 때 툴바의 쇼핑커넥트 버튼을 눌러 상품명으로 검색하고, 결과에서 상품을
골라 '추가하기' 까지 누른다. 제휴 링크는 이때 에디터가 직접 발급한다.

**엉뚱한 상품을 고르는 것이 최악이다.** `NEPTUNE` 과 `URANUS` 처럼 모델명만 다른 형제
상품이 나란히 뜨는 일이 흔한데, 이 둘은 문자열 유사도가 0.88 이나 된다. 비슷한 정도로
고르면 남의 상품에 내 글을 붙이게 되므로, 띄어쓰기와 괄호를 덜어낸 뒤 **정확히 같은
이름일 때만** 넣는다. 못 찾으면 카드를 포기하고 예전처럼 텍스트 링크로 떨어진다.
링크가 사라지지는 않는다.

> 쇼핑 커넥트 상품을 넣으면 네이버가 대가성 문구를 글 상단에 **자동으로** 넣는다.
> 본문 맨 위에 우리가 넣는 문구와 겹칠 수 있으니 발행 전에 확인하자.

### 카드에 들어가는 식별자

`article.html` 쪽은 우리가 직접 그리므로 식별자를 채워야 한다. 이 중 링크에서 읽어낼 수
있는 값은 두 개뿐이다.

| 값 | 어디서 오나 |
| --- | --- |
| `affiliateUrl` | 구매 링크에서 에디터가 붙이는 `ac` 파라미터만 뺀 주소 |
| `channelProductNo` | 구매 링크의 질의 문자열 |
| `creatorSpaceId` | `.env` 의 `NAVER_CREATOR_SPACE_ID`. 크리에이터마다 고정값이다 |
| `affiliateProductId` | 링크에 없다. 비운 채로 둔다 |

`naver.me` 단축 링크로 받으면 앞의 두 값은 리다이렉트가 도착한 주소에서 찾는다.
거기서도 못 찾으면 그 항목만 빠지고 카드는 정상적으로 그려진다. 본문에 들어가는 링크
주소는 언제나 원래 구매 링크 그대로라 제휴 추적은 유지된다.

## 이미지 우선순위

1. 상품 상세페이지 이미지
2. 상품 대표 이미지(썸네일)
3. Pexels / Unsplash 스톡
4. AI 생성

슬롯마다 어울리는 출처가 달라서, 전체 우선순위를 지키되 슬롯별로 선호 순서를 따로 둔다.
실사용 시나리오 자리에 스펙 이미지를 넣으면 어색하고, 주요 특징 자리에 스톡 사진을
넣으면 정보가 없기 때문이다.

| 슬롯 | 위치 | 선호 출처 |
| --- | --- | --- |
| hero | 도입부 | 썸네일 → 상세 → 스톡 |
| product | 상품소개 | 상세 → 썸네일 → 스톡 |
| feature | 주요특징 | 상세 → 썸네일 → 스톡 |
| lifestyle | 실사용 | 스톡 → AI → 상세 |
| infographic | 한눈에 보기 | 직접 그린 인포그래픽 (사진을 쓰지 않는다) |
| cta | 마지막 구매 안내 | 썸네일 → 스톡 → AI |

상세페이지 이미지는 860×5000 처럼 세로로 긴 경우가 많아 읽기 좋은 비율로 잘라 쓴다.
같은 사진을 크기만 바꿔 여러 번 올린 경우가 흔해서 지각 해시(dHash)로 중복을 걸러낸다.

### 이미지 지침

1. **글의 첫 번째 이미지는 상품 썸네일이다.** 도입부(hero) 자리에는 점수가 아니라
   썸네일 갤러리 순서로 골라 대표 이미지를 먼저 넣는다. 썸네일을 하나도 못 받았을 때만
   상세 이미지로 대신한다. 묶음 글은 첫 번째 상품의 썸네일을 쓴다.
2. **배송·교환·반품 안내, 쿠폰·적립 혜택 이미지는 쓰지 않는다.** 주소에 `delivery`, `refund`,
   `exchange`, `return`, `coupon` 같은 단어가 있으면 내려받기 전에 빼고, 내려받은 상세 이미지는
   점수 높은 4장을 AI 에게 보여 `product`(제품 설명) · `policy`(배송·반품 등 판매 정책) ·
   `other`(네이버쇼핑 쿠폰·적립·이벤트·브랜드 소개 등)로 나눈다(`ai/image_screen.py`).
   긴 이미지는 조각으로 자른 뒤 조각마다 검사하므로, 한 장 안에 섞인 배송·쿠폰 조각만 빠진다.
3. **제품을 설명하는 이미지만 넣는다.** `product` 만 남기고 `policy`·`other` 는 모두 버린다.
   검사하지 못한 나머지 상세 이미지도 버린다. 남은 게 없으면 썸네일이나 스톡으로 채운다.

이미지를 볼 수 없는 `AI_ENDPOINT=responses` 설정이거나 검사 호출이 실패하면 이 검사를
건너뛰고 경고만 남긴다.

## 사용

`--url` 은 **본문에 넣을 구매 링크**다. 브랜드 커넥트 제휴 링크를 그대로 넣으면 된다.
먼저 구매 링크를 따라가 내용과 이미지를 긁는다. 그걸로 상품 페이지를 읽지 못했을 때만
**실제 판매 페이지** 주소를 물어본다. 모르면 엔터를 치면 재시도·브라우저 창 단계로 넘어간다.
`--page-url` 로 미리 넘기면 그 주소를 먼저 긁는다.

```
구매 링크  https://naver.me/Gy3xcwOD

내용과 이미지를 긁어올 실제 상품 판매 페이지 주소를 알려주세요.
```

## 상품을 못 읽으면 멈춘다

가장 위험한 실패는 오류가 아니라 **그럴듯한 거짓말**이다. 상품 페이지가 죽어 있으면
크롤러는 메뉴와 푸터만 가져오는데, 그대로 두면 AI 가 "네이버 멤버십 적립", "통신판매
중개자" 같은 것을 상품의 특징이라 믿고 있지도 않은 상품의 리뷰를 완성해 버린다.

그래서 집필 전에 두 번 막는다.

1. `상품이 존재하지 않습니다`, `삭제되었거나`, `Access Denied`, 네이버 로그인 페이지로의
   리다이렉트를 감지하면 중단한다. 안내문은 페이지 앞부분만 본다. 후기 본문까지 뒤지면
   평범한 문장에 걸려 멀쩡한 상품을 막게 된다.
2. 가격 · 스펙표 · 상세 이미지 · 본문 길이 중 최소 두 개는 잡혀야 진행한다.
   못 찾은 항목을 알려주고 멈춘다.

판매 페이지가 막히면 구매 링크로 자동으로 한 번 더 시도하고, 그래도 안 되면 실제 판매
페이지 주소를 한 번 물어본다. 그래도 안 되면 45초씩
쉬었다가 최대 3회까지 다시 해본다. `smartstore.naver.com` 직접 주소는 자동 접근을
로그인 페이지로 돌려보내는 일이 잦은데, 같은 상품도 제휴 링크로 들어가면 통과하는
경우가 많아서다.

## 네이버 상품 정보를 읽는 방법

스마트스토어는 자동 접근을 막으면 화면 본문을 비우거나 로그인으로 보낸다. 억지로
페이지를 뚫지 않고, 아래 순서로 공개된 정보만 읽는다.

1. 블로그 발행에 쓰는 네이버 로그인 세션(`storage/naver_session.json`)이 있으면
   상품 페이지에도 그대로 쓴다. 한 번이라도 `python main.py post` 로 로그인한 적이
   있으면 세션이 남아 있다.
2. 화면을 스크롤하기 전에 `window.__PRELOADED_STATE__.simpleProductForDetailPage` 에서
   상품명·가격·대표 이미지를 읽는다. 본문이 비어도 이 JSON 은 첫 응답에 들어 있다.
3. 상세정보 탭을 열고, 있으면 **상품정보 펼쳐 보기** 를 눌러 접힌 상세설명을 펼친다.
4. 그다음에야 상세 이미지를 위해 스크롤한다. 페이지가 오류 화면으로 바뀌면 즉시 멈춘다.

## 네이버가 막을 때

짧은 시간에 여러 번 긁으면 네이버가 차단한다. 이때 HTTP 429 로 솔직하게 알려주기도
하지만, **멀쩡한 상품을 "상품이 존재하지 않습니다" 로 보여주기도 한다.** 삭제된 상품과
구분이 안 되니, 그 메시지를 봤다고 바로 상품이 없어졌다고 단정하면 안 된다.

특히 조심할 것이 하나 있다. 스마트스토어는 스크롤할 때 나머지를 지연 로딩하는데,
차단 상태에서는 그 요청이 실패하면서 **페이지 전체가 오류 화면으로 갈아치워진다.**
즉 멀쩡히 뜬 상품 페이지를 이쪽에서 스크롤하다가 스스로 망가뜨리게 된다.

```
goto+3s  : TEEBOX 플라스틱 30개입 ... 골프티 화이트 : 티박스 골프
스크롤 1  : TEEBOX 플라스틱 30개입 ... 골프티 화이트 : 티박스 골프
스크롤 2  : 상품이 존재하지 않습니다.      <- 여기서 뒤집힌다
```

그래서 스크롤 전 상태를 들고 있다가 페이지가 오류로 바뀌면 그 스냅샷을 쓰고, 이미지
수집 쪽도 오류 화면을 감지하면 즉시 스크롤을 멈춘다. 그때까지 모은 이미지는 지킨다.

**주 1회 포스팅이면 겪을 일이 거의 없다.** 연달아 테스트할 때만 문제가 된다.

단축 링크가 실제로 도착한 주소도 함께 보여준다. 제휴 링크는 어디로 가는지 눈에 보이지
않아서, 만료된 링크를 붙여놓고도 모르는 경우가 많다. 여기서 만료를 확인했다면 판매
페이지를 찾아 `--page-url` 로 넘기면 된다. 본문 구매 링크는 원래 제휴 링크가 유지된다.

`--desc` 로 상품 설명을 직접 넣으면 이 검사를 건너뛴다.

### 그래도 안 열리면 브라우저 창에서 직접 (`--browser`)

로그인 벽이나 캡차는 headless 로는 통과할 방법이 없다. `--browser` 를 붙이면 자동
수집이 막혔을 때 **브라우저 창을 띄우고 사용자에게 넘긴다.**

```bash
python main.py post --url "https://..." --browser
```

창에서 로그인·캡차를 끝내고 상품 페이지를 띄운 다음 터미널에서 엔터를 누르면,
**그때 창에 보이는 화면 그대로** 본문·스펙·상세 이미지를 읽는다. 창에서 다른 주소로
옮겨가도 되고, 그 주소가 실제 수집 대상이 된다. 이미지까지 같은 창에서 이어서 긁기
때문에 두 번 로그인할 일은 없다.

로그인까지 마쳤다면 그 세션을 `storage/naver_session.json` 에 저장해, 다음 실행부터는
자동 수집이 같은 벽에 막히지 않는다. 로그인하지 않은 채 상품 페이지만 봤을 때는
저장하지 않는다. 블로그 발행이 쓰는 로그인 세션을 덮어버리기 때문이다.

`--browser` 를 주면 재시도 대기(45초 × 3회)를 건너뛰고 한 번 시도한 뒤 바로 창을 띄운다.

### 상세 이미지가 0개면 옵션 없이도 창을 띄운다

상품 정보는 읽혔는데 **상세 이미지를 한 장도 못 건진 경우**도 같은 창으로 넘어간다.
`--browser` 를 붙이지 않았어도 그렇다. 상세설명 이미지는 끝까지 스크롤하고 펼쳐보기를
눌러야 지연 로딩이 도는데, headless 는 그 전에 로그인 벽이나 빈 화면을 받는 일이 잦다.

상세 이미지가 없으면 AI 가 상품을 눈으로 확인하지 못한 채 글을 쓰게 된다. 집중 포인트도
본문 텍스트만으로 뽑히고, 본문에 넣을 사진은 스톡으로 채워진다. 그래서 여기서만큼은
사람 손을 빌린다. 창에서 `q` 를 누르거나 파이프로 실행해 기다릴 사람이 없으면
이미지 없이 그대로 진행한다. 이미 창에서 수집한 뒤라면 다시 묻지 않는다.

`--no-images` 를 주면 이 단계도 건너뛴다.

## 업로드 전에 HTML 을 보고 제안으로 article 을 다시 쓴다

**지금은 꺼져 있다.** 기본은 제안 없이 바로 올린다. 다시 쓰려면 `.env` 의
`REVIEW_BEFORE_UPLOAD=true` 로 바꾸거나, 그 실행에만 `--review` 를 붙인다. `--md` 로 제안
파일을 넘기면 이 설정과 상관없이 그 제안으로 다시 쓴 뒤 올린다.

켜 두면 네이버 발행 직전에 `article.html` 미리보기가 열린다. 마크다운은 완성 원고가
아니라 **수정 제안**이다. Copilot 과 확인한 고칠 점을 `suggestions.md` 에 적으면
프로그램이 그 제안으로 article 을 다시 작성한다. 사진과 구매 링크 주소는 그대로 둔다.

`python main.py upload` 와 `python main.py post` 모두 같은 설정을 따른다.

```powershell
python main.py post --url "https://구매링크" --review
python main.py upload --from output/폴더 --review
```

## 티스토리에도 올려 구글에서 팔기

네이버 블로그는 네이버 검색에 강하고, 티스토리는 구글에 잡힌다. `post` 와 `upload` 는
원고를 네이버에 발행한 뒤, **같은 원고**를 [이슈상품 모음](https://wkkim97.tistory.com/category/%EC%9D%B4%EC%8A%88%EC%83%81%ED%92%88%20%EB%AA%A8%EC%9D%8C) 카테고리에 올린다.

1. 네이버에 `이슈상품` 카테고리, `상품리뷰` 주제로 바로 발행한다.
2. 발행 뒤 이동한 화면에서 글 주소(`https://blog.naver.com/아이디/글번호`)를 읽는다.
3. 묻지 않고 티스토리에 제목, 본문(글·사진·구매 버튼), 태그를 넣고 **임시저장**한다. 발행은 티스토리 글쓰기 화면의
   '임시저장' 목록에서 직접 한다. 바로 발행하려면 `.env` 에 `TISTORY_POST_MODE=publish` 를 넣는다.

본문은 `article.json` 을 티스토리용 HTML 로 바꾼 것이다. 사진은 글쓰기 화면이 쓰는 첨부 주소로
올려 카카오 CDN 주소를 받는다. 쇼핑 커넥트 카드는 네이버 전용이라 티스토리에는 같은 구매 링크의
버튼으로 들어간다. 네이버와 달리 대가성 문구를 자동으로 붙여 주지 않으므로 본문 맨 위에 직접 넣는다.

사진 몇 장을 못 올리면 그 사진만 빠지고, 하나도 못 올리면 예전처럼 네이버 글 링크만 올린다.
예전 방식(링크만)으로 돌리려면 `.env` 에 `TISTORY_CONTENT=link` 를 넣는다.

읽은 네이버 주소는 결과 폴더의 `naver.url` 에 남는다. `link` 방식에서는 주소를 읽지 못했을 때만
입력을 받고, `n` 을 넣으면 티스토리는 건너뛴다. `full` 방식은 주소 없이도 올린다.

티스토리 공식 글쓰기 API 는 종료되어, 네이버와 같이 브라우저로 올린다. 본문은 글쓰기
화면의 **HTML 모드**에 넣고, 그 모드 그대로 발행한다. 기본모드로 되돌리면 에디터가
태그를 고쳐 쓰므로 발행 전에는 되돌리지 않는다. 처음 한 번만 카카오 로그인이 필요하다.

```powershell
python main.py tistory-login
```

`.env` 기본값은 아래다.

| 항목 | 의미 |
| --- | --- |
| `TISTORY_BLOG_NAME=wkkim97` | `wkkim97.tistory.com` |
| `TISTORY_CATEGORY=이슈상품 모음` | 글을 넣을 카테고리 |
| `TISTORY_VISIBILITY=3` | 공개. 구글 수집 대상이다. `0` 이면 비공개 |
| `TISTORY_CONTENT=full` | 네이버와 같은 원고. `link` 이면 네이버 글 링크만 |
| `TISTORY_POST_MODE=draft` | 임시저장만 한다. `publish` 이면 바로 발행(이때 `TISTORY_VISIBILITY` 를 따른다) |

구글에 실제로 나오게 하려면 티스토리 관리에서 **검색 수집 허용**이 켜져 있어야 한다.
새 글이 검색 결과에 나타나기까지는 며칠 걸릴 수 있다.

**티스토리는 하루에 새 글을 15개까지만 공개 발행할 수 있다.** `TISTORY_POST_MODE=publish` 일 때만
해당한다. 넘으면 "하루에 새롭게 공개
발행할 수 있는 글은 최대 15개까지입니다" 알림과 함께 거절된다. 이때는 기다리지 않고 바로 멈춘다.
`--each` 중에 걸리면 남은 글은 네이버에만 올리고, 끝에 티스토리에 못 올린 글과 다음 날 실행할
`upload --from ... --tistory-only` 명령을 보여준다.

## 알아둘 제약

**네이버는 HTML 을 받지 않는다.** 스마트에디터가 실제로 지원하는 건 텍스트, 이미지,
인용구, 구분선, 그리고 툴바로 넣는 쇼핑 커넥트 상품 카드 정도다. 표는 자동화가
불가능해서 유니코드 기호로 시각적 구조를 만들어 넣는다. `article.html` 은
미리보기와 다른 플랫폼용이다.

**AI 이미지 생성은 기본 꺼져 있다.** Bayer myGenAssist API 에는 이미지 생성
엔드포인트가 없다. `.env` 의 `IMAGE_GEN_*` 에 외부 서비스(OpenAI 등) 정보를 넣으면
켜진다. 카테고리별 프롬프트 템플릿은 `media/prompts.py` 에 이미 설계되어 있다.

**네이버는 바로 발행한다.** `POST_MODE=publish`, `NAVER_CATEGORY=이슈상품`,
`NAVER_SUBJECT=상품리뷰` 가 기본이다. 카테고리나 주제를 못 고르면 다른 곳에 공개 발행되지
않도록 발행을 멈춘다. 임시저장만 하려면 `POST_MODE=draft` 로 바꾼다.

**대가성 문구는 지우지 않는다.** 쇼핑 커넥트처럼 판매 수수료를 받는 글에 이 문구가
없으면 표시광고법 위반이다. 본문 맨 위에 자동으로 들어간다. 기본 문구는 방문·구매가
잘 나는 쇼핑 커넥트 글의 표기를 따른다.

**주 1회 정도가 적당하다.** 매일 자동 포스팅하면 어뷰징 필터에 걸려 저품질 블로그로
분류될 수 있다.

## 사내망에서 생길 수 있는 문제

**SSL 오류로 외부 API 가 실패할 때.** 사내 SSL 검사 장비가 통신을 자체 서명
인증서로 가로채기 때문이다. `truststore` 가 파이썬이 윈도우 인증서 저장소를 쓰도록
바꿔서 해결한다. `requirements.txt` 에 포함되어 있다. 검증을 끄지 마세요.

**AI 응답이 비어서 올 때.** myGenAssist 는 `gpt-4o` 를 요청해도 `gpt-5-mini` 같은
추론 모델로 라우팅할 수 있는데, 이런 모델은 토큰을 추론에 먼저 쓴다. 한도가 모자라면
본문이 빈 채로 돌아온다. 프로그램이 추론에 몇 토큰을 썼는지 알려주므로 `max_tokens`
를 올리면 된다.

## 네이버 로그인이 안 될 때

쿠키만 보고 로그인 성공으로 처리하면, 만료된 세션인데도 "에디터에 내용 입력 중"으로
넘어간다. 지금은 글쓰기 화면이 실제로 열려야 로그인한 것으로 본다. 캡차가 뜨면
`.env` 의 `BROWSER_HEADED=true` 로 창을 띄운 뒤 직접 로그인한다. 네이버 홈이 보인
다음에 터미널에서 Enter 를 누르면 된다. 실패해도 창은 바로 닫지 않고, 로그인이
됐다면 세션을 저장해 다음 `upload` 에서는 다시 묻지 않는다.

업로드가 실패해도 원고는 `output/` 에 남아 있다. 처음부터 다시 만들지 말고
`python main.py upload` 로 올리기만 반복한다.

## 에디터 선택자가 바뀌었을 때

네이버는 CSS 클래스명을 수시로 바꾼다. "제목 입력란을 찾지 못했습니다" 같은 오류가
나면 `--debug` 로 실행해 `storage/screenshots/` 를 확인하고,
`publish/naver_blog.py` 위쪽의 선택자 목록에 새 값을 추가한다.
